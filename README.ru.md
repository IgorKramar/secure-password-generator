# Secure Password Generator

[English](README.md) · **Русский**

Библиотека TypeScript и CLI для Node.js для независимой случайной генерации, фраз EFF, паролей по политике сайта и существующего преобразования слова. Имя пакета npm — **`ts-secure-password-generator`**, команда — **`secure-passgen`**. Зависимостей времени выполнения нет.

Эти изменения **ещё не выпущены**. Версия пакета не изменена; существующий выпуск в реестре может не содержать новый API. Чтобы использовать описанную реализацию, соберите и установите tarball из этой рабочей копии.

## Установка и разработка

Поддерживаются линии Node.js **22, 24 и 26** с включённым глобальным Web Crypto. Используйте актуальный патч-релиз. Это LTS-линии в [официальном расписании](https://nodejs.org/en/about/previous-releases), проверенном 31.10.2026; Node.js 20 достиг EOL и больше не поддерживается. CI работает в Linux для всех трёх линий.

```sh
git clone https://github.com/IgorKramar/secure-password-generator.git
cd secure-password-generator
npm ci
npm run build
npm test
npm run test:package
npm pack
```

`npm ci` устанавливает зависимости разработки из lockfile. `npm test` сначала собирает проект. `npm pack` тоже выполняет сборку через `prepack`. Проверка пакета создаёт настоящий артефакт, устанавливает его в чистый временный проект с `--omit=dev`, затем проверяет импорты CommonJS/ESM, декларации, установленную команду и браузерную сборку. Временная папка после проверки удаляется.

Установите полученный tarball в приложение либо глобально для команды, заменив путь:

```sh
npm install /absolute/path/ts-secure-password-generator-0.0.2.tgz
npm install --global /absolute/path/ts-secure-password-generator-0.0.2.tgz
secure-passgen random --entropy 128
```

После выпуска этих изменений установка из реестра выполняется командами `npm install ts-secure-password-generator` или `npm install --global ts-secure-password-generator`.

## Библиотека

```ts
import {
  generateRandomPassword,
  getRandomPasswordInfo,
  generatePassword,
} from 'ts-secure-password-generator';

const random = generateRandomPassword(); // цель 128 бит -> 22 символа
const longer = generateRandomPassword({ length: 24 });
const readable = generateRandomPassword({ entropyBits: 129, excludeAmbiguous: true });
const info = getRandomPasswordInfo({ entropyBits: 128 });
// { length: 22, alphabet: 'abc...XYZ0123456789', alphabetSize: 62,
//   entropyBits: 130.99231882851126 } (здесь алфавит сокращён)
const legacy = generatePassword('apple', 16);
// Передайте пароли потребителю; не выводите реальные пароли в журнал.
```

CommonJS также поддерживается:

```js
const { generateRandomPassword, generatePassword } = require('ts-secure-password-generator');
```

`generateRandomPassword(options?)` возвращает строку. `getRandomPasswordInfo(options?)` проверяет те же параметры и возвращает `{ length, alphabet, alphabetSize, entropyBits }` без обращения к источнику случайности. Возвращаемая энтропия рассчитана для выбранной длины и может превышать запрошенную цель.

| Параметр | Контракт |
| --- | --- |
| `length?: number` | Целое от 1 до 1024; взаимоисключающий с `entropyBits` |
| `entropyBits?: number` | Положительная целочисленная цель; максимум 6097, с исключениями — 5972 |
| `excludeAmbiguous?: boolean` | По умолчанию `false`; удаляет ровно `0O1Il`: ноль, заглавную O, единицу, заглавную I, строчную l |
| Оба параметра размера отсутствуют | Цель 128 бит; явно переданный `undefined` считается отсутствующим значением |

Параметры должны быть обычным объектом. Неизвестные поля, массивы, `null`, неверные типы значений, дроби, `NaN` и бесконечности отклоняются во время выполнения, в том числе при вызове из JavaScript. Явная короткая длина допустима: длина 1 даёт примерно **5,95 бита**, а не 128 бит. Для произвольного алфавита и обязательных наборов символов используйте API политик ниже.

Пакет экспортирует типы `RandomPasswordOptions` и `RandomPasswordInfo`, строки `RANDOM_ALPHABET` и `AMBIGUOUS_CHARACTERS`, а также перечисленные ниже константы пределов. Внутренний сервис и случайный выбор индекса не входят в поддерживаемый публичный API.

## Алфавит и энтропия

Основной алфавит содержит ровно 62 уникальных ASCII-символа в следующем порядке:

```text
abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789
```

При `excludeAmbiguous: true` остаётся **57** символов. Каждая позиция выбирается независимо и равномерно. **Обязательных категорий нет**: результат только из строчных букв допустим.

Только для этого режима, при длине `L` и фактическом размере алфавита `A`:

```text
H = L × log2(A)
L = ceil(targetBits / log2(A))
```

Выбранная длина должна достигать цели и укладываться в предел; иначе генерация завершается ошибкой. Тесты округления перебирают все допустимые целочисленные цели для обоих алфавитов.

| Запрос | Размер алфавита | Длина | Расчётная энтропия |
| --- | ---: | ---: | ---: |
| По умолчанию / цель 128 | 62 | 22 | 130,99 бита |
| Цель 128, с исключениями | 57 | 22 | 128,32 бита |
| Цель 129 | 62 | 22 | 130,99 бита |
| Цель 129, с исключениями | 57 | 23 | 134,16 бита |
| Явная длина 16 | 62 | 16 | 95,27 бита |

Модель предполагает корректный криптографический источник, независимый равномерный выбор и отсутствие последующей фильтрации или отбора. Она не распространяется на пароли из слова, политики сайтов или выбор понравившегося результата из нескольких кандидатов.

## Парольные фразы

```ts
import { generatePassphrase, getPassphraseInfo, EFF_WORDLIST_INFO } from 'ts-secure-password-generator';

const phrase = generatePassphrase(); // цель 128 бит -> 10 слов, разделённых пробелами
const sixWords = generatePassphrase({ wordCount: 6, separator: '_' });
const info = getPassphraseInfo({ entropyBits: 128 });
// wordCount: 10, wordlistSize: 7776, entropyBits: примерно 129.248125
// combinations — точный bigint; minLength/maxLength ограничивают длину в символах.
```

Слова выбираются независимо **с возвращением** из [длинного словаря EFF](https://www.eff.org/dice). Повторения допустимы. Все 7776 уникальных записей сохранены без изменений, включая четыре слова с дефисами. Преобразования регистра, нормализации и фильтрации нет. Разделитель по умолчанию — один пробел; также доступны `_` и `.`. Эти символы не встречаются внутри записей словаря, поэтому последовательность слов в результате однозначна. Пустой разделитель и `-` отклоняются.

`wordCount` и `entropyBits` — взаимоисключающие положительные целые числа. Если оба отсутствуют, цель равна 128 бит; `undefined` считается отсутствующим значением. Количество слов — от 1 до 32, цель — от 1 до 413 бит. Для `W` слов из словаря размера `D`: `N = D^W`, `H = W × log2(D)`. Шесть слов дают примерно 77,55 бита; десять — 129,25 бита. Достижение цели проверяется точным сравнением `N` с `2^target`. Длина в символах переменная: слова содержат 3–9 ASCII-символов, поэтому 32 слова занимают не более 319 символов с разделителями. Требования сайта к категориям символов этот режим не обеспечивает.

`getPassphraseInfo()` возвращает `wordCount`, `wordlistSize`, `separator`, точное `combinations`, приближённое `entropyBits` и границы длины в символах `minLength`/`maxLength`. Экспортируются типы `PassphraseOptions`/`PassphraseInfo`, неизменяемые `EFF_WORDLIST`/`EFF_WORDLIST_INFO` и `PASSPHRASE_SEPARATORS`. Пока поддерживается только встроенный английский словарь; во время генерации сетевых запросов нет.

Исходный файл, SHA-256, атрибуция и описание преобразования включены в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Каждая сборка проверяет контрольную сумму исходника, все коды бросков кубиков, уникальность и соответствие JSON исходным словам. `npm run check:wordlist` запускает эту проверку отдельно. Данные EFF распространяются по CC BY 4.0, код проекта остаётся под MIT.

## Политики сайтов и точный подсчёт

```ts
import { generatePolicyPassword, getPolicyPasswordInfo, PasswordPolicy } from 'ts-secure-password-generator';

const policy: PasswordPolicy = {
  alphabet: 'abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789!@#$%^&*',
  requiredSets: ['abcdefghijklmnopqrstuvwxyz', 'ABCDEFGHIJKLMNOPQRSTUVWXYZ', '0123456789', '!@#$%^&*'],
  minLength: 12,
  maxLength: 64,
};
const password = generatePolicyPassword(policy, { entropyBits: 128 });
const info = getPolicyPasswordInfo(policy, { entropyBits: 128 });
// length: 21, alphabetSize: 70, entropyBits: примерно 128.537654
// combinations: 493957420278351331015146882126053376000n
```

Поля `PasswordPolicy`:

| Поле | Контракт |
| --- | --- |
| `alphabet` | Обязательная строка из 1–95 уникальных печатных ASCII-символов, U+0020–U+007E |
| `requiredSets?` | Не более 8 непустых строк уникальных символов из `alphabet`; нужен хотя бы один символ из каждого набора |
| `excludeCharacters?` | Уникальные символы из `alphabet`, которые нужно удалить; по умолчанию пустая строка |
| `minLength?` / `maxLength?` | Целые от 1 до 256, по умолчанию 1 / 256; минимум не превышает максимум |

Также экспортируются типы `PolicyPasswordOptions` и `PolicyPasswordInfo`. Обязательные наборы могут пересекаться: один символ способен выполнить несколько требований. Исключения применяются до подсчёта, включая опцию `excludeAmbiguous: true`. `generatePolicyPassword(policy, options?)` и `getPolicyPasswordInfo(policy, options?)` принимают те же три параметра размера/исключений, что random; действуют границы длины выбранной политики. `length` и `entropyBits` взаимоисключающие, цель по умолчанию — 128 бит. Общий предел цели для политик — 1681 бит; меньший алфавит или строгие границы могут сделать недостижимой и более низкую цель. Пустой алфавит, невыполнимые наборы, неизвестные поля, повторные символы, неподдерживаемый Unicode и неверные числовые значения явно отклоняются. Односимвольный алфавит допустим при явной длине с нулевой энтропией; положительную цель он не достигает.

Генератор считает **допустимые полные строки** таблицей динамического программирования по оставшейся длине и ещё не выполненным обязательным наборам. Затем равномерно выбирает один `BigInt`-ранг в пределах точного количества и декодирует его в пароль по числу допустимых продолжений. Исправления категорий в уже сгенерированном кандидате нет. Подсчёт учитывает пересечения наборов. CLI строит таблицу один раз и использует её для всей партии.

Для этого режима `H = log2(N)`, где `N` — точное число допустимых строк выбранной длины. Длина определяется целочисленным сравнением `N >= 2^targetBits`. Это существенно на границах: `2^128 - 1` не достигает 128 бит, даже если логарифм с плавающей точкой округляется до 128. `getPolicyPasswordInfo` возвращает `length`, фактические `alphabet`/`alphabetSize`/`requiredSets`, точное `combinations: bigint` и приближённое `entropyBits: number`. Для сериализации JSON преобразуйте `combinations` в десятичную строку: обычный `JSON.stringify` не сериализует `bigint`.

Меньший предел длины политики ограничивает таблицу 65 792 ячейками. Правила позиций, регулярные выражения, максимумы категорий, ограничения повторов и автоматическое определение требований сайта не поддерживаются. [examples/site-policy.json](examples/site-policy.json) — пример политики, а не утверждение о действующих правилах конкретного сайта. Тесты полного перебора сравнивают количество и каждый ранг с независимо построенными маленькими пространствами; это не формальное доказательство.

## Существующий API из слова и Unicode

`generatePassword(word: string, length: number): string` остаётся доступным. Для непустого ASCII-ввода в пределах ограничений сохраняется прежнее поведение:

1. Случайно меняется регистр букв слова.
2. При отсутствии соответствующей категории добавляются символ из `!@#$%^&*`, цифра и заглавная латинская буква.
3. Длина дополняется этими спецсимволами, цифрами и латинскими буквами.
4. Результат перемешивается алгоритмом Фишера — Йетса; каждый исходный символ сохраняется с учётом повторений, без учёта регистра букв.

Слово **не является seed источника случайности**. Выбранное пользователем слово добавляет предсказуемую структуру; этот режим не равномерен на множестве всех строк и **не получает оценку энтропии**. Строчные буквы не являются обязательной категорией.

**Контракт Unicode:** слово должно содержать 1–1020 ASCII-символов, от U+0000 до U+007F. Длина измеряется в ASCII-символах; в этом подмножестве она совпадает с числом кодовых единиц UTF-16 и кодовых точек Unicode. Кириллица, emoji, `ß`, комбинируемые знаки и некорректные суррогатные последовательности явно отклоняются. Нормализации, транслитерации и расширения символов при смене регистра нет. Для совместимости библиотека сохраняет управляющие ASCII-символы; интерактивный CLI принимает только печатный ASCII, U+0020–U+007E.

Длина должна быть целым числом от `word.length + 4` до 1024. Пустое слово, неверные типы, неконечная/дробная длина и чрезмерные запросы теперь вызывают ошибку вместо некорректного результата или цикла. Это намеренное ужесточение ранее непроверяемого ввода. Случайные индексы и регистр теперь выбираются без смещения; точные результаты и прежние смещённые распределения не сохраняются.

## CLI

```sh
secure-passgen random --length 24
secure-passgen random --length 20 --count 5
secure-passgen random --length 16 --exclude-ambiguous
secure-passgen random --entropy 128
secure-passgen random                           # цель по умолчанию: 128 бит
secure-passgen passphrase --entropy 128
secure-passgen passphrase --words 6 --separator _ --count 5
secure-passgen random --policy examples/site-policy.json --entropy 128
secure-passgen --help
secure-passgen from-word                        # интерактивный прежний режим
secure-passgen                                  # интерактивный выбор режима
```

Команды random и passphrase работают без терминала. `--policy` читает обычный файл UTF-8 JSON размером до 16 КиБ; путь и содержимое не повторяются в ошибках. Путь примера выше относителен рабочей копии репозитория; для установленной команды укажите путь к своему файлу. При успешной генерации в **stdout выводятся только пароли, по одному на строку**, с завершающим переводом строки. Приглашения и ошибки идут в stderr, справка — в stdout. Код завершения: 0 при успехе/справке, 1 при неверном вводе, ошибке генерации или EOF, 130 при интерактивном Ctrl+C. Вся партия генерируется до вывода, поэтому ошибка генерации не печатает неполный набор паролей.

Значения опций передаются отдельно: `--length 24`, а не `--length=24`. Числовые параметры принимают только десятичные целые числа. `16abc`, `16.5`, `1e2`, знаки и окружающие пробелы отклоняются. Неизвестные/повторные опции, пропущенные значения, лишние позиционные аргументы и сочетание `--length` с `--entropy` также вызывают ошибку. Количество по умолчанию — 1; `--count` применяется к random и passphrase. `--words` конфликтует с `--entropy`; passphrase не принимает `--length`, `--exclude-ambiguous` и `--policy`.

Без аргументов требуется терминал на **stdin и stderr**. Выберите `random` (по умолчанию), `passphrase` или `from-word`. Random спрашивает длину (пустой ответ означает цель 128 бит), количество и исключение неоднозначных символов. Passphrase спрашивает число слов (пустой ответ означает 128 бит), количество результатов и разделитель. From-word спрашивает слово и длину; этот сценарий также запускается через `secure-passgen from-word`. Ctrl+C отменяет ввод, Ctrl+D/EOF завершает его без зависания. Оба интерактивных входа вне терминала сразу завершаются с подсказкой; stdout можно перенаправить, оставив ввод и приглашения в терминале.

Исходное слово видно при вводе. Пароли могут сохраниться в истории экрана или записи терминала, а перенаправленный вывод — на диске. Программа не журналирует пароли, сама не сохраняет их в файл и не включает значения ввода в ошибки. Не вводите личные секреты в качестве исходного слова.

## Случайность и ресурсные пределы

Все режимы используют исключительно **`globalThis.crypto.getRandomValues`**. Подмены на `Math.random`, время, пользовательское слово или предсказуемый seed нет. Недоступный или неисправный криптографический источник вызывает понятную ошибку.

Для диапазона индекса `n` берётся беззнаковое 32-битное значение `x`, вычисляется `cutoff = 2^32 - (2^32 mod n)`, значения `x >= cutoff` отбрасываются, а для остальных возвращается `x mod n`. В принятом интервале каждому индексу соответствует одинаковое число значений. Один алгоритм используется для символов, слов, регистра и индексов перемешивания. См. также [Node.js `crypto.randomInt`](https://nodejs.org/api/crypto.html#cryptorandomintmin-max-callback) о необходимости устранения modulo bias.

Буфер содержит 256 беззнаковых 32-битных значений — **1024 байта**, меньше ограничения Web Crypto **65 536 байт за вызов**. Максимум 128 попыток на индекс останавливает неисправный источник, постоянно выдающий отбрасываемые значения; смещённого запасного выбора нет. Для используемых индексов символов, слов и перемешивания вероятность отбрасывания за попытку меньше `7776 / 2^32`. Ранг политики собирается из того же источника в пределах 2048 бит; лишние старшие биты маскируются, ранги за пределами количества вариантов отбрасываются. Вероятность отбрасывания ранга меньше половины за попытку; максимум — 128 попыток.

| Экспортируемая константа | Значение / применение |
| --- | --- |
| `MIN_PASSWORD_LENGTH` | 1, режим random |
| `MAX_PASSWORD_LENGTH` | 1024, random и from-word |
| `WORD_LENGTH_OVERHEAD` | 4 |
| `MAX_WORD_LENGTH` | 1020 |
| `MAX_PASSWORD_COUNT` | 100, партия CLI; максимум 102 400 символов паролей за запуск |
| `DEFAULT_ENTROPY_BITS` | 128 |

| `MAX_POLICY_PASSWORD_LENGTH` / `MAX_POLICY_REQUIRED_SETS` | 256 символов / 8 обязательных наборов |
| `MAX_POLICY_ALPHABET_SIZE` / `MAX_POLICY_ENTROPY_BITS` | 95 символов / 1681 бит |

Эти практические пределы ограничивают выделение памяти и работу генератора; это не рекомендации по стойкости. Односимвольный пароль допустим для API, но не является подходящей целью безопасности.

## Среды и проверка

Точка входа библиотеки — CommonJS с декларациями TypeScript; именованные импорты из Node ESM поддерживаются. В браузере нужны сборщик с поддержкой CommonJS, Web Crypto и поддержка ES2022 либо соответствующая транспиляция; в ядре нет импортов Node.js. Проверка пакета использует esbuild и контекст только с Web Crypto, без `process`, `require` и `Buffer`. Это проверка совместимости, а не сквозной тест в настоящем браузере. Готовой браузерной сборки и браузерного интерфейса нет.

CI выполняет `npm ci`, сборку, тесты и проверку пакета для PR, push в `main` и ручного запуска. Workflow выпуска проверяет сборку, тесты и упаковку перед `npm publish`. Слияние PR разработки не публикует пакет и не создаёт тег релиза.

Тесты используют управляемые последовательности для принятия/отбрасывания значений и преобразований, а также проверяют API и CLI. Они не требуют различия двух случайных паролей и не выводят корректность из статистики малой выборки. Проект **не проходил криптографический аудит или формальную верификацию**. Он не защищает пароли на скомпрометированном устройстве.

В отчётах [первого](docs/stage-one-verification.md) и [второго этапа](docs/stage-two-verification.md) зафиксированы исходное состояние, проверки и свидетельства удалённого CI. Дальнейшие задачи: опыты с профилями устройств, дополнительные словари и правила политик, LLM, формальные доказательства, браузерная песочница и хранилище.
