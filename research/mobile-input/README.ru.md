# Пилот ручного ввода на телефоне · протокол v1

[English](README.md)

**Статус: инструмент реализован; реальных измерений участников пока нет.** Автоматизированные запуски проверяют программу и не являются пользовательскими замерами. Подготовлен этап ③ карты проекта. Первый профиль — mobile, выбран владельцем проекта. Интерфейс опыта русский; образцы используют латиницу и английские слова EFF.

## Запуск

Из репозитория на поддерживаемой версии Node.js:

```sh
npm ci
npm run study:build
npm run study:serve
```

Для проверки на компьютере откройте `http://127.0.0.1:4173/mobile-input.html`. В `.study/mobile-input.html` находятся собранная библиотека, словарь, скрипт и стили. Внешних шрифтов, скриптов, аналитики и отправки результатов нет. CSP запрещает сетевые соединения и разрешает только встроенные скрипт/стиль с соответствующими хешами. Отпечаток сборки учитывает код и HTML и попадает в экспорт.

Для **реального опыта на телефоне** подключите компьютер и телефон к одной доверенной Wi-Fi сети:

```sh
npm run study:serve -- --lan
```

Откройте на телефоне `http://<локальный-IP-компьютера>:4173/mobile-input.html` в обычном браузере. Сервер отдаёт только страницу опыта, не принимает результаты и не ведёт журнал запросов. Остановка — Ctrl+C. HTTP в локальной сети предназначен для одноразовых экспериментальных образцов, не для генерации паролей аккаунтов. Настройки firewall и переадресация портов автоматически не меняются. При недоступной LAN можно разместить тот же HTML на доверенном HTTPS-сервере либо открыть файл в браузере, исполняющем локальный HTML. Просмотрщик документов может не исполнять JavaScript. Работу iOS/Android, экранной клавиатуры и скачивания необходимо проверить на выбранном телефоне: узкое окно настольного Chromium этого не заменяет.

После каждой завершённой или пропущенной попытки доступна выгрузка JSON. В конце сохраните его в игнорируемую Git папку `study-results/`. Перезагрузка страницы уничтожает данные в её памяти. Неполная сессия тоже выгружается; анализ сохраняет этот статус.

```sh
npm run study:analyze -- study-results/mobile-input-v1-p1.json
# Только JSON в stdout, без служебного баннера npm:
node scripts/analyze-study.cjs study-results/mobile-input-v1-p1.json
```

Анализатор принимает 1–100 обычных файлов UTF-8 JSON, до 128 КиБ каждый. Отклоняет неизвестные поля, несогласованные порядок/метрики, повторные номера участников и разные отпечатки сборок. Сначала соберите инструмент: используется `.study/model.cjs`. Вывод — описательные результаты каждого участника отдельно, без объединённого ускорения, теста значимости или утверждения о превосходстве.

## Зафиксированное сравнение

Вопрос: компенсирует ли отсутствие переключений регистра и цифрового слоя дополнительную длину на выбранном телефоне? Гипотеза — более длинный строчный формат может оказаться удобнее; это ещё не результат. Фраза — третий вариант сравнения, её преимущество не предполагается.

Везде цель **128 бит**, действующее криптографическое ядро, без выбора «приятного» результата, усечения, смены регистра и удаления повторов:

| Условие | Формат | Точное число вариантов | Расчётная энтропия |
| --- | --- | --- | --- |
| `random62`, контроль | 22 независимых символа из `abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789` | `62^22` | 130,992319 бита |
| `lower25`, кандидат mobile | 28 позиций из `abcdefghijkmnopqrstuvwxyz` | `25^28` | 130,027973 бита |
| `eff10`, фраза | 10 независимых слов EFF с возвращением, разделённых одним пробелом | `7776^10` | 129,248125 бита |

Цель общая, энтропия не идентична: разброс меньше 1,75 бита. В строчном алфавите исключена `l`; цифр и заглавных букв нет. Политика не требует категорий, поэтому равномерный выбор ранга эквивалентен независимым позициям. `25^27 < 2^128 <= 25^28`. Внутренние дефисы слов EFF сохраняются и могут требовать переключения слоя. После каждого нового ограничения надо пересчитать пространство и изменить версию протокола. Кандидат не обещает соответствие произвольному сайту. Формула не применяется к преобразованию пользовательского слова.

Тот же пример политики доступен через существующий CLI и включён в tarball:

```sh
secure-passgen random --policy examples/mobile-lowercase-policy.json --entropy 128
```

Здесь путь указан от корня репозитория; после установки используйте путь `node_modules/ts-secure-password-generator/examples/mobile-lowercase-policy.json`.

## Условия и процедура

Назначайте обезличенные номера участников последовательно (1–999), без поиска удобного порядка. Зафиксируйте модель, ОС/версию, браузер/версию, клавиатуру/версию, латинскую раскладку и технику ввода. Вертикальная ориентация, одна клавиатура и одинаковая техника сохраняются всю сессию. Отключите автокоррекцию, подсказки, жестовый ввод, вставку менеджером паролей; аппаратную клавиатуру не используйте. HTML-атрибуты этого запрашивают, но не управляют настройками ОС. Неотключаемые функции отразите в отчёте; не смешивайте условия молча. Не указывайте имя, серийный номер или пароли аккаунтов. Участие и передача JSON добровольны.

Образец постоянно виден, поле ввода **не маскируется**. Измеряется перепечатывание на одном устройстве, а не запоминание, ввод в скрытое поле входа или перенос со второго экрана. Кнопка показывает образец и запускает монотонный таймер: входят чтение и открытие клавиатуры. Точное совпадение при проверке завершает попытку. Ошибка оставляет тот же образец и продолжающийся таймер. Лимит — пять минут, доступен пропуск. Перегенерация для более лёгкого образца не предусмотрена. Между попытками можно отдыхать без работающего таймера.

Сначала три тренировки, по одной на условие, затем три блока по три условия: **12 попыток, девять измеряемых**. Номер участника задаёт одну из шести перестановок; блоки циклически сдвигают порядок. Каждое условие занимает каждую позицию один раз внутри участника; шесть последовательных участников покрывают все базовые порядки. Это балансирует позиции, но не устраняет обучение, усталость и перенос навыка полностью. Личный пилот полезен для поиска проблем инструмента, не для вывода о популяции. Если пилот требует изменения протокола, измените версию и анализируйте его отдельно.

После попытки оцените удобство от 1 (очень неудобно) до 7 (очень удобно). Можно указать запомнившееся число переключений регистра/слоя: пустое поле означает «неизвестно», а не ноль. Страница не видит физические экранные клавиши, расстояния между ними, настоящие переключения и все функции ОС. Число переключений — субъективная самооценка. Будущая модель перемещений должна задавать геометрию клавиатуры; её прогноз нельзя называть измеренным временем.

## Метрики и правила анализа

Основная описательная метрика — медиана времени **до правильного завершения** каждого условия внутри участника, без тренировок и отмеченных попыток. Время включает чтение, появление клавиатуры, исправления и отправку; это не чистая скорость печати. Рядом обязательно показываются количества успешных, записанных и запланированных попыток, пропуски и тайм-ауты. Быстрый ввод небольшой успешной части не означает общего улучшения.

Дополнительно: ошибки первой отправки и число попыток с отправкой, расстояние редактирования первого ответа, неверные отправки, события удаления, задержки первого ввода/отправки, удобство и самооценка переключений. Расстояние Левенштейна считает замены, вставки и удаления без нормализации; это не число опечаток. События `input` не равны физическим нажатиям: клавиатуры и браузеры группируют их по-разному.

Заранее определены отметки: уход страницы в фон, попытка вставки/перетаскивания, автозамена, композиционный ввод и события от скрипта. Такие попытки остаются в JSON и счётчиках, но исключаются из основного сравнения. Вставка блокируется в пределах доступных событий браузера. Отсутствие отметки не доказывает отсутствие любой помощи ОС. Тайм-аут — цензурированное наблюдение на 300 секундах, не успешное завершение за это время. Пропуски не удаляются и не заменяются повторной попыткой; незаписанные попытки остаются отсутствующими. При необходимости отдельно покажите чувствительность результата к включению отмеченных попыток. Не объединяйте неоднородные устройства и не считайте девять повторов девятью людьми.

Анализатор проверяет схему и согласованность, не происхождение данных: редактирование JSON не аутентифицируется. В отчёте нужны реальные условия, число участников, исключения/пропуски, сравнения внутри участников и ограничения. До выполнения процедуры человеком результата об удобстве нет.

## Остальные профили и границы

| Профиль | Предлагаемые условия | Что изучать | Статус |
| --- | --- | --- | --- |
| Desktop | Физическая латинская клавиатура, фиксированная раскладка, две руки | Shift/символы, перемещения, неоднозначность, длина | Описание; измерений нет |
| Mobile | Вертикальная экранная латинская клавиатура, фиксированная техника | Регистр/слои, перемещения, длина, неоднозначность | Инструмент готов; замеры на физическом телефоне ожидаются |
| TV | Фиксированная сетка, пульт, заданные правила переходов и удержания | Перемещения, подтверждения, смена слоя, длина | Описание; генератора с оптимизацией и измерений нет |

Пилот не реализует оптимизацию траектории, симулятор TV, новый публичный API или общую браузерную песочницу. Исследовательский инструмент отделён от npm runtime; в пакет включён только пример строчной политики. Английские слова EFF могут быть менее знакомы русскоязычному участнику — знание языка необходимо учитывать в отчёте.

Основание — [статья Sadik et al., SOUPS 2026](https://www.usenix.org/conference/soups2026/presentation/sadik) о затратах ввода на устройствах. Ускорения из статьи — прогнозы моделей для её алгоритмов, не измерения этого проекта. Автотесты не означают аудит, формальное доказательство или подтверждённое преимущество.

## Проверка инструмента

```sh
npm test
npx playwright install chromium
npm run test:study
npm run test:package
```

Для установленного Chromium: `STUDY_CHROMIUM_PATH=/path/to/chromium npm run test:study`. Проверки запускают локальный HTTP-сервер и окно 390×844: полная сессия и экспорт, исправление ошибки, отметки помощи/фона, тайм-аут, отсутствие crypto, сетевых запросов приложения и хранения, отсутствие горизонтального переполнения. Ввод явно синтетический. Набор из 268 тестов на этом этапе также проверяет контролируемые часы, порядок, энтропию, схему экспорта и неполные данные. Не сохраняйте автотестовые выгрузки как результаты участников.
